# 高原样线 · 观鸟巡护工时透视

岭北湿地巡护站有 7 名轮值观察员，沿苇湾湿地、石岭草甸和背风灌丛开展固定样线巡护。巡护小组原先用纸质时刻表和手机备忘录登记，值班员周末合并为透视表。零观测容易被当成漏填，折返记录有时贡献了较大的计数但巡护工时不完整，每周重跑时旧数据变化又会让已经发出的数字对不上。本工作台把巡护出发、逐种观察、返站复核和快照关联起来，给站务人员发布带工时口径的透视汇总。

| 角色 | 页面 | 业务权限 |
|---|---|---|
| operator · 野外观察员 | 样线登记、野外记录、工时透视 | 登记巡护班、录入观察与返回、编制透视 |
| reviewer · 值班复核员 | 巡护复核 | 按是否完成样线与最低工时确认统计资格 |
| viewer · 站务联络员 | 四个页面 | 查看巡护状态、明细记录和冻结透视 |

## 巡护剧本

1. 11 月 16 日白羽组在苇湾湿地完整走了 60 分钟，登记鸭类 4 只。石岭草甸另有 50 分钟和百灵 5 只。
2. 11 月 23 日 08:00，晨光组从苇湾湿地 WX 出发，08:45 返回。鹤类 6 只、鸭类 2 只。
3. 09:45，雪线组因浅滩漫水未到终点。返站单记了鸭类 12 只和 20 分钟，复核标为剔除。
4. 11:00，晚霞组巡护同一湿地，到 11:45 未观察到鸟。出站和回站时间齐全，在返回表单明确确认零观测。
5. 11:50，值班员核对实际 45 分钟达到样线 35 分钟门槛，晚霞组按有效零保留。
6. 12:10，青篱组折返，即使观察到 50 只鸭类，也要说明水位抬高并登记为剔除。
7. 14:00，按样线×ISO 周编制双周快照。苇湾湿地第 48 周为 8 只 / 1.50 小时，即 5.33 只/小时。
8. 15:00，流云组在背风灌丛的记录另行通过复核。重新编制地表×周的鸭类快照，新快照纳入其工时，旧快照保留当时结果。

初始样线册有 3 条样线、7 个巡护班和一份双周冻结快照，包含有效零、提前折返、待复核和计划班四种业务记录。

## 工时口径

按高原当地时间（北京时间）登记，同组同样线同日唯一。逐种观察事件必须在开始后八小时内，返回时间不得早于末个已登记的观察点。未到终点必须填写折返原因，完整巡护无观察时必须显式记零。低于线路最低工时或未完成线路，经站务复核后从计数与工时中一并排除。工时是返回时间减开始时间，按秒存入透视结果。

透视维度可在样线、地表和 ISO 周之间选两个。日期窗口最多 92 天跨度，含两端。每格累加有效巡护的计数、工时、班数及确认零的班数，再以计数除以工时得到只数/小时。边际合计同样从可加量重算。有效零贡献工时；无有效工时显示缺值。限定物种仅过滤分子。Worker 保存行列、聚合、有效班 ID、剔除原因和待复核班 ID，后续变更在新快照中体现。示例鸟种为现场粗分组，记录的是观察只数。

## 运行

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

本机前端 http://127.0.0.1:18295，FastAPI 文档 http://127.0.0.1:19295/docs，宿主机 PostgreSQL 端口 17795。演示账号为 `operator@demo.local`、`reviewer@demo.local`、`viewer@demo.local`，默认密码 `Demo2026!`。首次初始化前可设置 `DEMO_PASSWORD`，端口与其他环境变量见 `.env.example`。

| 服务 | 技术与职责 |
|---|---|
| frontend | Nginx + 原生 HTML/CSS/JS，API 同源反代 |
| backend | Python 3.11、FastAPI、Psycopg、JWT |
| worker | 执行 PostgreSQL 持久队列任务，冻结透视 |
| db | PostgreSQL 16，持久化命名卷 |
| redis | Redis 7，登录限流与连通性检测 |

本地开发时启动数据库与 Redis，配置 `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET` 与 `SEED_DEMO`。进入 `backend` 安装 `requirements.txt`，运行 `uvicorn app:app --reload` 和 `python worker.py`。前端代理需转发 `/api/`。 `docker compose stop` 保留演示数据，`docker compose down -v` 清除该项目演示卷。

- `backend/schema.sql` 保存样线、巡护班、鸟种事件与工时快照。 `domain.py` 定义输入校验、接口及 fixture，`transects.py` 实现复核流转，`pivot.py` 实现多维聚合。
- `frontend/patrol.js` 管理样线与快照读取、工时格渲染及时间格式，`fieldbook.js` 实现四页，`field.css` 定义日志样式。
- 共享枚举有角色及 Worker 状态（`backend/core.py`、`backend/worker.py`、`frontend/base.js`）、巡护状态（`backend/schema.sql`、`backend/transects.py`、`frontend/patrol.js`、`frontend/fieldbook.js`）、鸟种分类、地表类别和透视维度（`backend/schema.sql`、`backend/domain.py`、`backend/pivot.py`、`frontend/patrol.js`、`frontend/fieldbook.js`）。

许可证见 `LICENSE`。

## 巡护质量与站内发布

天气条件页登记起点和返回的能见度、风力、降水。对已启用此记录的班次，巡护复核前要核签两端记录，观测时刻须在实际班次内。任一点能见度低于 100 米、风力达到 6 级或遇强降水，即使巡完全程也从工时和观察数中剔除。历史无此项的班次使用旧资格规则。

值班员可为完整班次安排两位观察者独立报数。等待两份后计算按种计数的加权 Jaccard，即每种较小计数之和除以较大计数之和；双方全零视作一致。低于 80% 时可为原样线登记后续补走班，原记录仍可追查。

统计发布页由复核员签发已全量核对的冻结透视，生成 CSV 和站内岗位收件记录。更正须采用更新的同日期、同轴和同鸟种范围快照，并覆盖旧版接收岗位。旧版仍可以下载、校对，回执只在本系统登记。
